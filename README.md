# 夜谭

> 由大语言模型担任「守秘人（KP）」的克苏鲁的呼唤（Call of Cthulhu 7th）单人跑团引擎。纯前端、零依赖、零构建，浏览器打开即可运行。

[![License: CC BY-NC 4.0 + Additional Terms](https://img.shields.io/badge/License-CC%20BY--NC%204.0%20%2B%20Additional%20Terms-lightgrey.svg)](./LICENSE)

**本项目仍处于开发阶段。** 本项目按"现状"提供，版权所有人不对使用本项目产生的任何直接或间接损失承担责任。

夜谭把一场 COC 跑团搬进终端式界面：玩家扮演调查员，AI 扮演守秘人，负责叙事、NPC、检定、线索与危机推进。它不是普通聊天机器人，而是一套围绕 LLM 构建的、带规则约束、状态记录与长程记忆的单人跑团系统。

---

## 核心功能

- **AI 守秘人**：接入 OpenAI 兼容 API，通过系统提示词约束叙事节奏、检定触发、NPC 行为与恐怖氛围。
- **COC 7 版规则引擎**：支持属性、技能、衍生属性、d100 检定、明骰/暗骰、奖励骰/惩罚骰、SAN、战斗与技能成长。
- **分层长程记忆**：按系统设定、静态模组、当前状态、近期回合、压缩历史分层管理，并按 token 预算动态注入上下文。
- **空间拓扑系统**：地点连接关系、区域划分、阶段解锁路径，防止 AI 凭空生成地点或跳过过渡叙事。
- **NPC 情绪三轴**：好感度/恐惧/烦躁三维情绪模型，性格特质影响情绪变化率，情绪极值触发行为（逃离、结盟、拒绝）。
- **守门人机制**：AI 自审 + 本地正则预检双层拦截，识别玩家违规声明（超能力、自动成功、跳过检定），零额外 AI 调用。
- **随机事件系统**：模组可定义随机事件表，按地点/阶段/轮数触发，概率检定 + 一次性控制，触发后注入叙事提示。
- **实体记忆索引**：自动追踪 NPC、物品、地点的首次/最后出现轮次，生成记忆摘要注入上下文，防止 AI 遗忘。
- **角色创建**：包含属性掷骰、职业选择、技能点分配、年龄修正与可选角色立绘生成。
- **15 分钟试玩教程**：短案《雨夜电台》，三种职业各有专属开场剧情，支持简化掷骰建卡或预设卡。
- **本地存档**：多存档槽、自动存档、导入/导出 JSON，数据保存在浏览器本地。
- **文生图集成**：支持直接 API 或 curl 配置，用于角色立绘、NPC 与关键场景图。
- **主题与沉浸效果**：多套主题、打字机效果、音效、环境音与骰子动画。
- **模组校验工具**：启动时自动检查模组 JSON 结构完整性，输出校验报告。

## 新手指南

### 这是什么？

夜谭是一个**单人克苏鲁跑团游戏**。你不需要找朋友当主持人，AI 会扮演守秘人（KP），负责讲故事、扮演 NPC、判定骰子结果和推进剧情——你只需要扮演你的调查员，做出选择即可。

### 为什么需要 API Key？

夜谭本身不包含 AI 模型，它是一个"框架"——负责规则判定、状态记录和界面呈现。AI 的叙事能力来自外部的大语言模型（如 GPT、Claude、DeepSeek 等），你需要提供一个 API Key 来连接这些模型服务。可以把它理解为你和 AI 之间的"通行证"。

### 如何获取 API Key？

1. **选择一个模型服务商**。以下是一些常见选择：
   - [OpenAI](https://platform.openai.com/)（GPT 等）
   - [Anthropic](https://console.anthropic.com/)（Claude 等）
   - [DeepSeek](https://platform.deepseek.com/)（DeepSeek-V3 等，价格较低）
   - [硅基流动 SiliconFlow](https://siliconflow.cn/)（国内可用的聚合平台，支持多种模型）
   - 其他任何提供 OpenAI 兼容 API 的服务商均可

2. **注册账号并充值**。大多数服务商需要绑定支付方式或预充值，按使用量计费（通常每次游戏花费在几分钱到几毛钱之间）。

3. **在控制台创建 API Key**。登录后一般在"API Keys"或"密钥管理"页面可以生成，复制保存好——它只会显示一次。

### 下载后怎么用？

**第一步：下载并打开**

1. 点击本页面右上角的绿色按钮 `Code` → `Download ZIP`
2. 解压到任意文件夹
3. 用浏览器打开 `index.html`（推荐 Chrome 或 Edge）

> 如果双击打开后功能异常，可以用本地服务器方式启动：在解压目录打开终端，运行 `python -m http.server 8000`，然后浏览器访问 `http://localhost:8000`

**第二步：配置 API**

1. 打开页面后，点击右上角 **SET** 按钮进入设置
2. 在"文本模型 API"部分：
   - **供应商**：从下拉列表选择你的服务商，或选"自定义"手动填写
   - **Base URL**：选择供应商后会自动填入；自定义时需手动填写接口地址
   - **API Key**：粘贴你从服务商控制台获取的密钥
   - **模型名**：填写你要使用的模型名称（如 `gpt-4o`、`deepseek-chat` 等）
3. 点击"测试连接"确认配置成功

**第三步：开始游戏**

- **第一次玩？** 建议从主菜单的 **15分钟试玩** 开始，体验简化版短案《雨夜电台》
- **想玩完整模组？** 选择"新游戏"，按流程创建角色后即可开始
- 游戏过程中输入文字描述你的行动，AI 会回应并推进剧情；需要检定时系统会自动掷骰

**提示**：所有数据（API Key、存档、设置）都保存在你的浏览器本地，不会上传到任何服务器。清除浏览器数据会导致存档丢失，建议定期使用"导出存档"功能备份。

## 配置说明

在设置面板中可以配置以下内容：

1. **文本模型 API**：选择供应商或自定义 OpenAI 兼容接口，填写 Base URL、API Key 与模型名。
2. **模型参数**：可调整 temperature、top_p、max_tokens、频率惩罚与存在惩罚。
3. **图像生成 API**：可选，用于角色、NPC 与场景图生成。
4. **游戏设置**：主题、难度、打字速度、音效、自动存档与存档管理。

所有 API Key、设置和存档均保存在浏览器 `localStorage` 中。项目没有后端服务，API 请求由浏览器直接发往你配置的模型服务商。

## 工程亮点

这个项目的核心命题是：**如何让一个不可靠的叙事者（LLM）跑在一套可靠的规则系统（COC 状态机）之上**。几条经过实测打磨的设计决策：

### 确定性归引擎，叙事归模型
骰子、时间、阶段推进、战斗开始/结束、结局判定等确定性事件全部由引擎接管，模型只负责讲故事。引擎对模型输出的结构化标记（`[STAGE_FLAG:]` `[ENDING:]` 等）做容错归一化（全角括号、转义残留、未知标记拒收），单个畸形标记不再能瘫痪整局状态机。

### 追认叙事，意图为门
引擎不把模型的叙事拽回状态机，而是**追认**叙事进度——但追认必须以玩家意图为门：玩家说"出发去电台"且叙事写到抵达，状态才推进；模型自说自话提前换幕会被意图门拦截。出发意图跨轮持久化，解决"上轮出发、下轮抵达"的漏接。

### 分层 Prompt 与缓存友好
System prompt 按变化频率分四层（L0 静态规则 / L1 当前幕指令 / L2 回合状态 / L3 末尾提醒），变化越频繁越靠后，最大化前缀缓存命中。幕指令单一来源、按幕注入，与末尾提醒形成首尾夹击。

### 测试驱动的修复循环
由 AI 测试员出具结构化验收报告（通过项/失败项/案发链/归因），每条失败附引擎终态摘录；人类测试员提供体感清单（节奏、选项质量、沉浸感）。修复按"招聘方归因方式"而非技术严重度排优先级。调试日志记录每轮发送消息、原始回复、解析标记与处理前后的引擎状态（`storyState` / `storyStateAfter`），跨会话残留自动清理。

### 对模型只立正向规则
实测验证：纯负向约束（"不许重复选项"）只会得到换皮服从（"询问苏蔓"→"询问苏蔓的看法"）；无触发器的氛围指令会被静默忽略。有效的指令形如"每个选项必须从本轮叙事最后一拍引出"、"本轮把第 N 级身体异样织入叙事"——给路标，而不是只划悬崖。

### 空间拓扑约束叙事边界
地点连接关系由模组定义，引擎注入可达地点列表；AI 只能从当前地点的连接中选择目标，不得凭空生成新地点。跨区域移动需描述过渡（城区→海岸线需经过道路），阶段推进时自动解锁新路径。这套机制防止 AI 跳过关键叙事节点或破坏地理逻辑。

### 情绪系统性格驱动
NPC 情绪不是简单的数值加减，而是性格特质影响变化率：高神经质的人好感度波动剧烈（负面×1.5，正面×1.3），低神经质的人反应迟钝（×0.7）。情绪极值触发行为（烦躁≥3→拒绝合作，恐惧≥3→逃离），让 NPC 不只是"好感度数字"，而是有性格的反应者。

### 守门人双层拦截
玩家违规声明（"我有魔法"、"直接成功"）分两层拦截：本地正则预检零延迟拦截明显违规，不调 AI；AI 自审在检定裁定时二次检查，处理模糊边界。两层互补，既省 API 调用又覆盖复杂场景。

## 技术架构

项目保持无框架、无构建、无依赖。每个 JS 模块以全局单例对象存在，由 `index.html` 按依赖顺序通过 `<script>` 加载，`Main` 在 `DOMContentLoaded` 后统一初始化。

这个选择的好处是分发简单、可以双击运行；代价是模块之间通过全局命名空间协作，长期维护时需要持续控制耦合。

### 长程记忆

`memory-system.js` 是核心模块。它把上下文拆为多层：

- `system`：系统级约束。
- `static`：模组静态设定。
- `state`：当前世界、角色、案件与线索状态。
- `episodic`：近期回合。
- `compressed`：压缩后的历史摘要。

系统会按 token 预算裁剪、召回和压缩内容，避免长对话中出现遗忘、状态漂移和 NPC 人设漂移。

### 规则与叙事边界

项目尽量让程序负责确定性规则，例如骰子、属性、技能、存档和结构化状态；让 LLM 负责叙事表达、氛围、角色反应和线索呈现。这也是后续继续优化的主要方向。

### 安全边界

源自 LLM 输出、导入存档或用户输入的内容，在进入 `innerHTML` 渲染边界前应统一经过 `Utils.escapeHtml()` 转义，避免恶意存档或模型输出注入脚本。
